## 阶段 4：四个问题的分析与核对（约 1 天）

每个问题都按下面的 5 个步骤完成。**按 Q1 → Q2 → Q3 → Q4 顺序做，每题做完再开始下一题。**

### 每题的固定流程

**步骤 A：AI 通过 MCP 写 SQL 并执行**
- **提示模板**（替换【问题】）：
  ```text
  通过 sqlite-readonly MCP 访问 orders 表和 orders_v 视图。规则：
  1. 只写 SELECT。
  2. 字段名含空格要用双引号。
  3. 订单数用 COUNT(DISTINCT "Order Id")，不要用行数代替。
  4. 延迟率按 metrics.md 的订单级口径计算，不要用行级平均。
  5. 比例用 100.0 * SUM(...) / COUNT(...)，避免整数除法。
  先给出 SQL 并说明口径，再执行。
  问题：【问题】
  ```
- **产出**：SQL 和结果，追加到 `sql/queries.sql`，注释写明问题和口径。

**步骤 B：AI 用 pandas 独立复算**
- **做什么**：AI 在 `scripts\03_validate.py` 中写对应题号的函数。**该函数只读取 `orders` 表，不参考 `sql/queries.sql`**，以保证两种计算方式相互独立。
- **运行**：
  ```text
  C:\Users\31451\.claude\venvs\skills\Scripts\python.exe -I scripts\03_validate.py Q1
  ```
- **产出**：pandas 的结果，写入 `validation.md` 的草稿。

**步骤 C：Excel 核对 1 个数字（AI 完成，你检查）**
- **做什么**：AI 在 `工作簿1.xlsx` 的新工作表中用透视表或公式算一个数字（如 Q1 某地区的延迟率，Q3 某月的订单数）。
- **检查**：与 SQL 和 pandas 的结果一致（允许 0.01 个百分点或 0.01 的误差）。

**步骤 D：比对并记录**
- **做什么**：在 `validation.md` 中记录每题三方的结果：SQL、pandas、Excel。
- **通过标准**：计数完全相等，比例差值不超过 0.01 个百分点，金额差值不超过 0.01。
- **不一致时**：找原因（口径？整数除法？日期？NULL？），把过程写入 `ai_log.md`。

**步骤 E：Excel 图表（AI 完成，你检查）**
- **做什么**：在 `analysis.xlsx` 中为该题建立工作表，放结果表和图表。

  - Q2：运输方式对比表（平均计划天数、平均实际天数、延迟率）。
  - Q3：月度订单量折线图（标注 2018 年不完整）。
  - Q4：品类表（订单数、销售额、延迟率），附柱状图。

## 常见问题

| 现象 | 处理 |
|---|---|
| 脚本报错找不到 CSV | 确认路径是 `data\raw\DataCoSupplyChainDataset.csv`，文件没有被误改名 |
| 导入后中文或字段名乱码 | 确认编码为 ISO-8859-1 |
| MCP 工具没有出现 | 确认 `claude mcp list` 中有 `sqlite-readonly`，并重新启动 Claude Code |
| SQL 报错 "no such column" | 字段名有空格，必须用双引号，如 `"Order Region"` |
| 比例结果是 0 或 1 | 整数除法，分子加 `100.0 *` |
| 三方结果不一致 | 先检查口径是否一致，再检查分组字段是否有空值，最后检查日期解析 |
| Excel 公式结果为空 | 公式未重新计算，需要让 Excel 计算后再读取，不能直接读取未计算的公式 |
