## 1. 目标岗位与能力

- **目标岗位**：供应链 / 物流运营 / 生产计划类实习生（来源：`D:\work\实习\通用简历-修改稿.md` 的求职意向）。
- **简历背景**：快递分拨一线经验，研究方向为运输组织优化，有 Excel 和 Python 基础。项目要与这条线对齐，不另起一个方向。
- **项目要证明的能力**（面试官视角）：
  1. 能把配送、运输、排产中的问题拆成可以用数据回答的问题，并定义指标。
  2. 能用 SQL 和 Excel 找到问题出在哪里、影响多大。
  3. 能给出可执行的建议：改哪个环节、谁来做、看什么指标判断是否有效。
  4. 能用 AI 提高效率，并且知道 AI 会错在哪里、怎么验证。
  5. 能说清数据局限，不把相关关系说成因果关系。
- **不做**：开发工程（不搭系统，不写 agent 框架）、机器学习、仪表盘系统、财务分析、邮件自动化。

## 4. 分析问题（4 个，对应目标岗位）

每题包括：**业务问题 → 数据问题 → 指标 → 可能的行动**。

| 题号              | 对应方向 | 业务问题                      | 数据问题与指标                              | 可能的行动                                |
| --------------- | ---- | ------------------------- | ------------------------------------ | ------------------------------------ |
| **Q1 地区配送延迟**   | 物流运营 | 哪些地区延迟率高，且订单量大，应优先改善？     | 按地区统计订单数和订单级延迟率                      | 优先排查"延迟率高且订单量大"的地区，看是承运商、仓配还是承诺时效的问题 |
| **Q2 运输方式承诺时效** | 运输组织 | 各运输方式的承诺天数与实际天数是否匹配？      | 按运输方式统计订单数、平均计划天数、平均实际天数、延迟率         | 承诺天数明显偏短的运输方式，调整承诺时效或调整承运方式          |
| **Q3 月度需求节奏**   | 生产计划 | 订单量在各月如何波动？哪些月份需要提前备料或排产？ | 按月统计订单数和订单级延迟率（2018 年只有 1 月，不做年度结论）  | 找出订单量高峰和延迟率跳升的月份，作为排产和备货的参考          |
| **Q4 品类需求与履约**  | 供应链  | 哪些品类订单量大、销售额高，但履约表现差？     | 按品类（`Category Name`）统计订单数、销售额、订单级延迟率 | 高需求且高延迟的品类，检查供应和配送环节，优先保障            |

**每题的交付物**：一张结果表，一张图（Q1 柱状图，Q2 表，Q3 折线图，Q4 柱状图），2 到 3 句结论，1 条建议，以及不确定性说明。

**结论写法**：发现 → 可能原因（标注是推测还是已验证）→ 建议 → 需要看的指标。不把推测写成事实。

## 5. 指标口径（最小集）

| 指标 | 定义 | 注意 |
|---|---|---|
| 订单数 | `COUNT(DISTINCT "Order Id")` | 不用行数代替订单数 |
| 订单级延迟率 | 同一订单内任一行 `Late_delivery_risk = 1`，该订单记为延迟；延迟订单数 ÷ 订单数 | 行级延迟率只作对照，报告中说明差异 |
| 平均计划 / 实际天数 | 每单取一行后求平均 | 避免同一订单被重复计算 |
| 销售额 | `SUM(Sales)` | 毛销售额 |
| 比例写法 | `100.0 * SUM(...) / COUNT(...)` | 避免整数除法 |

口径在 `metrics.md` 中定稿，之后不随意改动。

## 7. 面试准备（物流运营 / 供应链方向）

**3 分钟讲稿结构**
1. **业务问题**（20 秒）：配送延迟和承诺时效如何影响客户体验和成本，我想找出问题在哪里。
2. **数据与口径**（30 秒）：公开数据，18 万行，6.6 万个订单；延迟用订单级口径。
3. **发现**（60 秒）：讲 1 到 2 个结论，每个都要有数字和原因（推测要标注）。
4. **建议**（30 秒）：改哪个环节、谁来做、看什么指标判断是否有效。
5. **AI 与验证**（30 秒）：AI 做了什么，一次真实的错误，怎么发现和修正的。
6. **局限**（10 秒）：公开数据、2018 年不完整、延迟标志是定义性关系。

**常见追问**
- 你怎么定义"延迟"？为什么用订单级？
- 如果按月排产，你怎么用这份需求数据？2018 年只有 1 月，怎么处理？
- 运输方式和延迟是因果关系吗？（不是。延迟标志由实际天数和承诺天数决定，是定义性关系。）
- 承诺天数应该怎么定？数据能支持到什么程度？
- 如果建议执行了，怎么判断有没有效果？（设基线，看延迟率、订单量在几周内的变化。）
- AI 错了你是怎么发现的？
- 如果让你负责这份数据的日常监控，你会怎么做？
