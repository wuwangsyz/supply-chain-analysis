# 配送履约分析：结论与建议

> 面向业务同事，对应 `项目计划.md` 第 4 节的 4 个问题。
> 数据：DataCo 公开供应链数据集（180,519 行订单项、65,752 个订单、2015-01 至 2018-01 共 37 个月）。**公开样本，不是企业真实数据。**
> 每个数字都能在 `analysis.xlsx` 对应工作表找到；口径见 `metrics.md`，三方核对见 `validation.md`，断点判定见 `break_analysis.md`。

---

## 读结果之前要知道的三件事

1. **延迟率按订单计**：同一订单内任一行标记延迟，该订单记为延迟。本数据中 45,902 个多行订单里没有一个出现订单内标志不一致，所以行级（54.8291%）与订单级（54.8242%）只差 0.005 个百分点。
2. **`Late_delivery_risk` 由实际天数与承诺天数之差定义**，不是外部观测的迟到事件。因此"某类延迟率高"只能说明它的承诺与实际不匹配，**不能推出承运商服务差**。
3. **2017-10 有一个记录结构断点**：每单行数从 3.0 变为 1.0。它破坏了"量"的可比性（行数、订单数、金额、件数），没有破坏"率"的可比性（延迟率、运输方式占比、折扣率）。涉及量的结论一律限定在同一窗口内。

## Q1 地区配送延迟：哪些地区应该优先改善

**发现**：全期订单级延迟率 54.82%（36,048 / 65,752）。23 个地区的延迟率在 49.51%（Canada，309 单）到 57.55%（Central Africa，556 单）之间，跨度不到 8 个百分点。延迟订单绝对量最大的是 Western Europe 5,585 单（10,010 单、55.79%）和 Central America 5,156 单（9,396 单、54.87%），两地合计占全部延迟订单的 29.8%。

**可能原因**：地区之间的差距很小，且延迟率最大的两个地区样本都不足 700 单（标准误约 2 个百分点以上），不构成"某些地区特别差"的证据。单量最大的 Western Europe 比总体高 0.97 个百分点，与其标准误（约 0.5 个百分点）的 95% 区间宽度相当，接近抽样波动。**已验证**：这个"地区间差异小"的结论在断点后窗口重复成立——7 个两段都出现的地区，延迟率差值最大 1.63 个百分点，其余 6 个都在 1 个百分点内。

**建议**：不做按地区排查的动作。要分配核查资源，按延迟订单数而不是延迟率排序，先看 Western Europe 和 Central America——两地合计约 1.07 万单延迟，占三成，改善这里的任何一点都会在总量上体现。责任环节：区域履约／客服运营，承运商管理配合。

**跟踪指标**：这两个地区的订单级延迟率与延迟订单数，按周看 4–8 周，先定基线（当前 55.79% 与 54.87%）。若某地延迟订单数下降而订单量不变，才算改善；只看延迟率容易被订单量波动干扰。

## Q2 运输方式承诺时效：承诺天数与实际是否匹配

**发现**：承诺天数越短的方式，延迟率越高，且实际天数与承诺天数系统性错位。

| 运输方式 | 订单数 | 平均承诺天数 | 平均实际天数 | 订单级延迟率 |
|---|---|---|---|---|
| Standard Class | 39,324 | 4 | 4 | 38.13% |
| Second Class | 12,778 | 2 | 4 | 76.72% |
| First Class | 10,079 | 1 | 2 | 95.27% |
| Same Day | 3,571 | 0 | 0.48 | 46.15% |

排除 2,855 个"已取消"订单后（其中 1,650 单的实际天数已超过承诺，却没有被标记为延迟，这是数据的定义方式，不是计算错误），方向不变、数值更高：First Class 100.00%、Second Class 79.99%、Standard Class 39.85%、Same Day 48.37%。

**可能原因**：**已验证的部分**是结构关系——延迟标志在"实际天数 > 承诺天数"时成立（0 个例外），所以承诺偏短必然抬高延迟率。**未验证的部分**是为什么承诺这么设：数据里没有承运商时效、没有分拣与干线时长，无法区分是承诺定得不合理还是运输能力确实不足。另外，实际天数在 2–6 天之间近似均匀分布、First Class 恒为 2 天，这个形态不像真实物流运营，更像生成数据。

**建议**：先校准承诺，再谈改善履约。Second Class 按实际均值 4 天、First Class 按实际均值 2 天重设承诺（更稳妥的做法是按实际天数的 P85 分位设定）。在承诺改准之前，First Class 的延迟率会一直停在 95% 以上，这个指标就没有信号可用。责任环节：物流产品／时效承诺配置。

**跟踪指标**：重设后各方式的延迟率应回落到与 Standard Class 同一量级（40% 上下）；同期必须盯客户侧指标——承诺天数变长可能推高下单放弃率和客服投诉，只看延迟率会把改善误判为纯收益。

## Q3 需求节奏：哪些时期需要提前备料或排产

**发现**：断点前的 11 个完整季度（2015Q1–2017Q3）订单数在 5,141–5,309 之间，延迟率 53.94%–55.51%，没有季节性。2017Q4 记录值 6,280（较前一季度约 +19%），但同期每单行数由 3.0 降为 1.0。

**这个 +19% 不能当作需求高峰**：它与记录方式变化在同一个月发生，数据里无法区分两者。按不同口径，2017Q4 的订单数落在 2,146 到 6,280 之间（相差约 3 倍），主口径取假设 A 的 5,195（与前三季持平）——**这是假设，不是观测**。

**更要紧的是：四个需求代理在断点两侧给出的方向都不一致。**

| 指标（月均） | 断点前 33 个月 | 断点后 4 个月 | 变化 |
|---|---|---|---|
| 行数（订单项） | 5,211 | 2,139 | −59% |
| 订单数 | 1,738 | 2,101 | +21% |
| 件数 | 11,372 | 2,198 | −81% |
| 销售额 | 1,037,826 | 634,117 | −39% |

同一时期、同一批业务，四个量一个升三个降、幅度从 39% 到 81%，说明断点两侧连"业务规模"本身都不可比，换指标救不回来。

**可能原因**：断点来自数据生成或导出环节（证据链见 `break_analysis.md` 第 4–5 节：每单行数在一个月内跳变、客户复用从 4.65 单/人变为 1.00 单/人、两段记录 ID 首尾相接、订单号缺口率从 16.6% 变为 0.26%，而履约参数一位小数都没变）。**已验证**：延迟率、运输方式占比、折扣率跨断点稳定，因此这些率不受影响。

**建议**：**不用这份数据做排产或备料参考**，包括不用"件数"这个看似更硬的口径。要给出可用的需求节奏，需要数据集的版本说明（2017-10 发生了什么）或换一个记录结构一致的时段。本项目能给的方法论是：先看每单行数、再看需求指标。责任环节：需求计划，数据侧提供记录方式说明。

**跟踪指标**：不适用。这份数据不支撑需求侧的跟踪基线。

## Q4 品类需求与履约：哪些品类量大但履约差

**发现**：在断点前窗口（2015-01 至 2017-09，57,349 单）里，总体订单级延迟率 54.77%。销售额最高的 5 个品类——Fishing、Cleats、Camping & Hiking、Cardio Equipment、Women's Apparel——延迟率在 54.42%–55.09% 之间，与总体差距都在 1 个百分点内。**没有"量大、销售额高、履约又差"的品类。**

32 个品类里延迟率最高的是 Golf Bags & Carts（68.85%，61 单）和 Lacrosse（60.12%，341 单），但样本量分别只有 61 和 341 单，标准误约 5.9 和 2.7 个百分点。它们的延迟率与总体（54.77%）相差 14.1 和 5.3 个百分点，即 2.4 和 2.0 个标准误；32 个品类同时比较，按双侧 5% 的门槛本来就有约 1.6 个品类会偶然越线，所以这两个偏离不构成异常。

**可能原因（推测）**：延迟与品类无关，说明它不发生在品类特有的环节（供应、拣货），而发生在各品类共用的环节——末端配送的时间承诺与实际运输时长，这与 Q2 指向同一个位置。要区分这两者需要承运商与分拣环节的数据，本数据没有。

**建议**：品类层面不做"优先保障"动作，把资源投向 Q2 的承诺时效校准。若要核查小品类，先累积样本：延迟率的标准误要降到 1 个百分点以内，单个品类约需 2,500 单，本数据只有 10 个品类达到这个量级。责任环节：品类运营维持现状，物流产品接手。

**跟踪指标**：以总体延迟率（断点前 54.77%）为基线，按品类看与总体的差值；只在品类样本 ≥2,500 单时才解读差值。断点后窗口的品类数据不参与（各品类只有 3–30 单，且品类构成已换了一批）。

## 建议的动作顺序

| 顺序 | 动作 | 责任环节 | 依据 |
|---|---|---|---|
| 1 | 重设 Second Class 与 First Class 的承诺天数 | 物流产品 | Q2：承诺 2 天／实际 4 天、承诺 1 天／实际 2 天 |
| 2 | 核查资源按延迟订单数排序，先看西欧与中美洲 | 区域履约 | Q1：两地占全部延迟订单 29.8% |
| 3 | 索取 2017-10 的记录方式说明，再决定能否做需求分析 | 数据侧 | Q3：四个需求代理方向不一致 |
| 4 | 品类层面不动作，小品类累积样本后再看 | 品类运营 | Q4：量大品类延迟率与总体差不到 1 个百分点 |

## 局限（必须与结论一起讲）

1. 公开样本数据，不是企业真实数据；实际天数分布近似均匀、延迟标志由承诺与实际天数之差定义，都不具备真实运营的性质。
2. 2018 年只有 1 月，不做任何 2018 年结论。
3. 2017-10 的记录结构断点使所有"量"的指标跨段不可比；本报告涉及量的结论都限定在同一窗口。
4. 延迟是定义性关系，本报告没有任何因果结论。
5. 订单级与行级延迟率在本数据中几乎相等（差 0.005 个百分点），但这是"订单内标志完全一致"的结果，换一份数据不一定成立，不能当成通则。

**一句话总结**：这份数据能支持的最强结论是——延迟问题在各地区、各品类之间分布均匀，因此它更可能出在"承诺时效"这一层：First Class 与 Second Class 的承诺天数明显低于实际所需，先改承诺，延迟率这个指标才有可用性。需求节奏无法从这份数据得出，因为 2017-10 的记录结构变化让行数、订单数、件数、销售额四个口径互相矛盾。
